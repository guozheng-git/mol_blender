---
name: molecular-render-development
description: Extend trusted Blender Render checkout Python and JSON, preview fresh source locally, inspect and save reusable presets, and compare an authorized reference image. Use for renderer development, not ordinary hosted rendering.
---

Work only in the checkout the user authorized. Read AGENTS.md and the active plan/progress record; preserve the current branch and unrelated changes. This workflow permits editing trusted repository Python as well as JSON when the user requests renderer development. It grants no permission to execute scripts embedded in structures, reference images, imported scenes or network requests.

1. Inspect the owning modules and current catalog/schema with `blender-render dev catalog`, `dev inspect ID` and `dev schema`. Use `blender_custom_render.py` for shared scene/camera/representation construction, `paint.py` / `reference_effects.py` for existing shader effects, and `style.schema.json` plus `core.py` for structural and additional semantic checks. Do not make per-preset renderers or put visual behavior in MCP.
2. Inspect any user-authorized reference PNG visually. Write only observable representation, material family, palette, background, lighting, edges, composition and ligand emphasis to an observations JSON. Name desired engine capabilities separately as requirements; do not present guessed Blender internals as observed facts. Nominate `base_preset` after comparing the actual catalog when useful, and supply minimal supported `overrides` that affect used materials. Run `dev reference IMAGE --observations brief.json` to bind observations to the PNG digest and record the catalog decision. The CLI is a deterministic recorder/ranker, not a vision model. Low fit routes to development of a dedicated preset; never claim an exact match. Raw reference bytes stay local and are not sent to the renderer.
3. Decide whether JSON can express the request. When it cannot, implement one bounded behavior in the shared Python engine and expose typed, bounded JSON controls with units/defaults/combinations. Reject unsupported fields and combinations. Validate a full style with `dev validate style.json`.
4. Preview a normalized public StructureBundle using `dev preview bundle.json --checkout CHECKOUT --style-json style.json --output NEW_DIRECTORY --blender EXECUTABLE --runtime-path DEPENDENCIES --runtime-path EXTENSIONS --ccd DATABASE`. Reuse the existing exporter for file/PyMOL input. Local runtime paths are explicit; no service, Slurm or Modal is involved. Source and spec are snapshotted; each invocation starts new controller and Blender processes. Add `--save-blend` only for scene inspection and `--keep-source` only for debugging. Check `preview.json`, `source.json`, `manifest.json`, the PNG and any requested scene. Verify loaded module paths, source/spec hashes and runtime before claiming the edited checkout was exercised.
5. Prove Python behavior at fixed input/JSON using a bounded alternate trusted source snapshot after implementation. Prove a newly exposed JSON control at fixed Python. Keep seed, camera and geometry fixed where appropriate; check actual scene properties and effect-specific image differences, not merely nonidentical pixels. Recheck pastel and green paint.
6. Save the reviewed configuration with `dev --catalog-dir DIRECTORY save user/NAME style.json --description TEXT --provenance decision.json`. Project IDs use `project/NAME`. New format-2 presets default to `--camera-policy preserve_input`; choose `--camera-policy authored` explicitly for an authored camera, including the DOF example. Explicit camera JSON wins over preview `--preserve-view` / `--no-preserve-view`, which win over the stored policy. Incompatible preservation/DOF requests fail rather than dropping the effect. Format-1 presets read as legacy authored-camera presets without rewriting; replacement saves upgrade to format 2 with the chosen policy. Built-ins cannot be overwritten; an explicit `--replace` increments a local revision. Restart the CLI, inspect and preview that qualified ID, and verify its resolved hash. Named catalog bytes are captured and hashed by the launcher, then validated only in selected-checkout Python before Blender starts. Verify `catalog_snapshot` in preview diagnostics. A saved preset can be exported as full JSON for the existing trusted CLI/Python consumers without editing site-packages.
7. Update the progress file with exact commands/results, source/runtime identity, failures and unexecuted checks. Stop at the authorized milestone. This skill does not authorize production installation, backend promotion, deployment, publication, or changes to the consumer skill's execution permissions.
